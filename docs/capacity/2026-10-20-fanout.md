## Profile and design

The baseline already JSON-serialized once per project event, with no per-subscriber tracker/event database reads, event-time authorization queries or application response-write callbacks. It passed strings to each response and ignored backpressure. The candidate frames UTF-8 once, shares buffers for common replay positions and coalesces a fixed 4 ms window. One project membership query is applied individually to subscribers; event and registration boundaries are captured before asynchronous authorization. Queues include Node-buffered bytes, are bounded to 1 MiB / 64 batches, and disconnect a stalled client after 15 seconds while other clients continue.

Opaque project-epoch/sequence IDs support exact replay after Last-Event-ID. The process-local journal retains 60 seconds / 10,000 frames / 8 MiB. Unauthorized callers receive 404; stale, evicted and cross-project cursors receive authorized 409 responses requesting refresh. Native browser reconnects preserve their cursor. See [design](../realtime-fanout.md), [raw numbers](2026-10-20-fanout-numbers.json), [condensed exploratory receipts](2026-10-20-fanout-exploratory.json) and [cleanup receipt](2026-10-20-fanout-cleanup.json).

## Reproduction

Use a clean checkout of the recorded source revision for archived warm-up behavior. The current preload corrects registration order, and a new run with that correction is not represented here. Supply a dedicated disposable test database privately; use fresh external output paths.

```sh
: "${DATABASE_URL:?Set a dedicated disposable test database URL}"
BASELINE_DIR=$(mktemp -d)
git show 5346b64:dist/services/sse.js > "$BASELINE_DIR/sse.js"
git show 5346b64:dist/routes/pm.js > "$BASELINE_DIR/pm.js"
npm run build
CAPACITY_OUTPUT=$(mktemp -d)/fanout-abab.json
node scripts/with-test-db.ts node scripts/capacity-fanout.ts "$BASELINE_DIR" "$CAPACITY_OUTPUT"
```

The comparator normally schedules four runs per population; this archive was intentionally stopped after the first 3,000 pair. All final starts use sixteen slots and explicit 120-second connection/full-roster readiness. Up to six reader workers normally own at most 500 real sockets each; each retains independent receipt timestamps and a bounded roster-parse cache. Ordinary release startup defaults and all production authorization, pool and slow-reader bounds are unchanged. No hosted endpoints or user project data were involved.

## Correctness, revert proofs and gates

Tests cover 3,000 shared-buffer sinks, one serialization, order, queue/stall limits and bounded replay. Real HTTP/Postgres tests deny strangers, forged cross-project cursors and revoked direct/group members. A production process disconnects its last viewer, receives three independent CLI updates to a non-git tracker and replays exactly those three on reconnect. Browser tests exercise native cursor retention and replacement recovery.

Reverting only prepareFanout to the old direct shared-string loop fails 15/16 core/access cases. Reverting the heartbeat permission guard fails 1/1; removing the membership decision causes a real revoked-viewer private-frame leak. Reverting captured authorization boundaries fails both late-event and new-viewer cases. Browser guard reversion fails 2/5; expired-startup and independent-worker receipt regressions each fail 1/1. Reverting only setup interception fails 1/1. The final baseline-replacement regression fails 1/1 when only preload registration order is reverted; exact restoration passes.

Measured source passed npm run release:check and bun run release:check under Node 22 and 26 ([CI](https://github.com/unbraind/pm-web/actions/runs/39494784168)); each execution passed 713/713 suite tests, 2/2 real capacity tests and all four packed npm/Bun current/minimum-host scenarios. Coverage floors are unchanged, duplication is zero and tests have no skipped/canceled outcomes. See [validation receipt](2026-10-20-fanout-validation.json); final PR-head gate results are linked in the PR.
