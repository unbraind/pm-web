## Design and preserved guarantees

Each admitted subscriber now reads owner/direct/group access and its display name
in one fresh SQL statement. The old shared-user path needed ownership, shared
access and profile statements. Fan-out still refreshes authorization before every
slice of at most 32 viewers, but supplies only that slice's distinct principals.
The SQL result is bounded to those principals instead of the entire project roster.
There is no authorization cache or revision-invalidation assumption.

Presence already serializes once per snapshot. Its full-roster wire protocol,
fixed one-second coalescing, 32-viewer socket slices, admission/pool bounds,
queue bytes/batches, stalls, replay retention, cursors and deduplication are retained.
The production-process regression still uses a plain tracker and a server PATH
containing only Node. See [the protocol](../realtime-fanout.md).

2000 initializations execute SQL. Profiling is excluded from capacity medians.
