Latency begins at the authoritative committed history entry's millisecond mutation timestamp (includes persistence after timestamp assignment), never at HTTP acknowledgement or CLI exit. The table measures each write's last first-delivery across all subscribers; incomplete writes are excluded from latency quantiles and counted as loss. JSON also contains all subscriber/write-pair and per-transport quantiles, per-subscriber missing sequences/duplicates, and before/after health counters. Generic workspace invalidations do not count as item delivery.

This is a finite local experiment with co-located server, writers and readers, fresh small trackers and continuously draining clients. It does not establish sustained throughput, slow-reader buffer bounds, proxy/browser behavior, multiple server instances, reconnect replay, large-project costs, actual pm-gpt/MCP execution, or hosted-stack capacity. The bus is enabled; cross-instance fanout is not exercised. CPU percentages refer to one core. RSS is sampled, not a memory bound. An unobserved bottleneck remains unidentified.
